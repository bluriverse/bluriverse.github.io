Bluriverse — Active Directory Security Lab

A personal lab for securing, auditing and hardening a hybrid Microsoft infrastructure.

An environment built from scratch to practise Active Directory security in realistic conditions, measure the effect of remediation and connect on-premises identity security with Zero Trust principles and Microsoft Entra ID.

01Context

Active Directory is still the heart of identity in most organisations — and one of the first targets during a compromise. To understand its risks beyond theory, I built a personal environment where I can configure, break, audit and fix things without production constraints.

The goal is not to replicate a company, but to have a realistic playground: a two-DC domain, structured accounts and groups, and a link to Microsoft Entra ID to study hybrid identity.

02Technical architecture

  • Windows 11 host running VirtualBox.
  • DC01: Windows Server 2019 with Desktop Experience — administration, GPMC, audit tooling.
  • DC02: Windows Server Core — reduced attack surface, remote and PowerShell administration.
  • bluriverse.corp domain on an internal 192.168.10.x network, with NAT access for updates.
  • Free Microsoft Entra ID tenant and Entra Connect to study hybrid synchronisation.

03Risks studied

Excessive privileges
Accounts in privileged groups without need, overly broad delegations, admin accounts used for daily work.
No segmentation of admin tiers
A Tier 0 account logging on to a workstation exposes its credentials: separating tiers limits attack paths.
Legacy or unnecessary components
SMBv1, the Print Spooler service on domain controllers, Remote Registry: services that widen the attack surface.
Lack of traceability
Without a suitable audit policy, sensitive changes and privileged logons go unnoticed.
Misconfigurations
Default settings, weak password policies, stale accounts: the kind of findings a tool like PingCastle reports.

04Methodology

  • Baseline: initial PingCastle audit and inventory of accounts, groups and GPOs.
  • Prioritisation: findings ranked by impact and ease of remediation.
  • Remediation in batches: every change is documented and scripted where possible.
  • Re-assessment: a new audit after each batch to measure the actual effect of the fixes.
  • Knowledge capture: documenting the approach, the choices made and remaining open points.

05Measures implemented

Directory structure
Organising OUs, lab accounts and role-based groups.
Tier 0 / 1 / 2 model
Structuring roles and administration levels, with dedicated accounts per tier.
Security GPOs
Hardening Windows and Active Directory settings through Group Policy.
Attack surface reduction
Disabling or restricting SMBv1, the Print Spooler and Remote Registry depending on lab scenarios.
Event auditing
Configuring the audit policy on domain controllers to trace sensitive operations.

06PowerShell automation

Repetitive lab operations are scripted so they are reproducible and traceable. Details are covered in the dedicated identity-management automation write-up.

  • CSV-based onboarding: creating and updating accounts.
  • Disabling accounts.
  • Idempotent processing where relevant: re-running a script never creates duplicates.
  • Operation logging.
  • Checks and remediation.
  • Backup and restore within the lab.
  • Documenting operations.

07Observed results

After remediation, the lab's PingCastle risk score went from 70 to 20. This figure reflects the state of this test environment at a given point in time: it measures the effect of the fixes and does not describe a production audit.

Beyond the score, the lab helped me formalise a repeatable approach: assess, prioritise, fix, measure, document.

08Learning goals

  • Understand the risks of an Active Directory infrastructure.
  • Reduce the attack surface.
  • Structure privileges.
  • Improve traceability.
  • Automate repetitive tasks.
  • Document an audit and remediation approach.
  • Connect on-premises identity security with Zero Trust concepts and Entra ID.
